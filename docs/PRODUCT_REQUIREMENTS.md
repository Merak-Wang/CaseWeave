# 络寻 · CaseWeave 产品需求

络寻 · CaseWeave 是企业会话与工单证据检索智能体，以工单为检索和交付单位，关联会话原文作为证据。本文定义查询条件、证据判断、持续交互与确认结果的产品语义。组件实现见 [架构说明](ARCHITECTURE.md)，验证方法见 [评测策略](EVALUATION_STRATEGY.md)。需求规格不代表所有数据和模型配置均达到相同质量。

## 1. 用户、任务与交付

用户是服务工单查询工作人员和领导。他们用自然语言收集某类问题的历史工单，为下游根因标签聚类、产品相似故障排查/改进、用户反馈分析提供依据。产品内部不开展业务聚类、打标和统计分析。

交付由**确认工单集合、可追溯检索报告、下载接口**组成。报告提供确认数量、一至两段简短业务总结和必要引用，帮助下游理解和复用结果；不附工单清单或成段原文，引用可按需打开。报告总结不能替用户编写未经工单证实的根因或改进结论。首版下载具体格式可以随试用调整，工程起点见 [工作台与交付](design/WORKBENCH.md)。

对业务工单只读。任务状态、用户反馈、报告版本和 Wiki 是产品自身可写数据。知识更新不改变业务工单。

工作台支持连接已授权的 Mongo 数据源，按时间范围、来源及工单身份、标题、摘要字段下载并清理数据，再写入共用的 MySQL/Milvus，生成标准检索向量索引。只有完整发布的就绪数据集可用于新查询。用户可以准备和选择多个数据集；新任务固定所选数据集的来源与索引快照，已有任务、报告和下载不随首页选择变化。

## 3. 快查询与自然语言条件

先对原始 query 执行一次 LLM 查询理解与规划，产出关键词、完整自然语言业务判据、语义检索改写及算子步骤；规划完成后，关键词 OR 宽召回与原句/有用改写的向量召回并行执行。向量召回保留余弦相似度大于等于 0.65 的全部命中，不以 Top-K 补入低于阈值的工单；100 条是每批读取数量，不是结果上限。关键词 OR 全部字面命中不受向量阈值限制。自定义检索对完整召回并集完成二分类，不能把页面大小解释为结果上限。

- 关键词按 OR 跨工单字段宽召回，枚举全部字面命中；分页、向量 Top-K 与模型窗口不截断字面集合。
- AND/OR/NOT、括号、主体、对象、时间、已完成与待办理状态、纳入与排除条件保留在自然语言判据中，由模型依据证据判断；不把词表或查询改写当作业务硬条件。
- 初轮允许语义改写；原始向量请求保持原句。检索假设可以扩展候选，不能放宽最终确认条件，也不能制造事实。
- 两路按稳定工单身份合并，保留来源与通道。明确 ID、字段、时间和字面要求始终约束最终判断，缺字段不得猜值。
- 用户补充、可选相关性反馈与原始要求一同进入规划和算子上下文。补充沿用候选与已读证据，旧输入代次的结果不得覆盖新条件。
- 相对日期固定任务时刻与时区，区分创建、处理和历史状态；数据没有的事实保持未知。

首次有用候选尽快展示。后台关键词枚举尚未完成、某通道仍运行时显示实际状态；不必等全部工单下载到前端才进入后续分析。

## 4. 知识状态、专家与进一步检索

工单自定义检索使用四步流程，不要求人工反馈或逐条确认：

1. 一次 LLM 规划产生关键词 OR、向量检索改写与完整业务判据。对象别名、业务简称与区分性症状用于发现候选，不能改变用户要求。
2. 并行执行关键词 OR 全部字面命中与 cosine>=0.65 向量召回，按工单身份去重。学习范围限于该并集。选样方法可替换，判断额度不因策略改变而增加。
3. 开启学习时，对并集内样本生成是/否＋confidence 伪标签，在同批标签内选择小模型和阈值，判断其余候选。选择先满足原查准率与召回率目标；不可达时，在选择集查准率至少 60% 的候选中按标准 F0.5（β=0.5）选择阈值与模型，偏重查准率并兼顾召回率，再用 Balanced Accuracy 等指标打破平局。低于 60%、单类标签或交叉验证依据不足时显示“不知道”，以未完成结束，仅交付已有确认工单，不发布整并集预测。OOF 指标只表示训练教师标签一致性，不是独立业务准确率。关闭学习时，无反馈算子直接判断候选并集。
4. 教师与获准发布的小模型的最终是集合形成确认结果，可直接导出 XLSX，保留判断来源。

教师和融合均为严格二分类，低confidence不生成第三类。技术故障单独显示失败、不补成no、不参与训练。可记录交叉验证与离线独立留出的教师一致性指标作为研究证据，但不把它们改造为用户未要求的交付审批或重新标注机制。confidence、投票比例与相似度不是已校准人工准确率。来源缺失、服务故障或取消如实报告未完成，不伪造标签。

抽样判断可将按查询和知识目录选中的领域知识带入同一次抽样模型请求，与该请求判断的工单建立可追溯引用关系。界面把这项实际调用显示为“领域知识辅助判断”，不得据此虚构一次独立专家调用；只有 Agent 确实委派并运行的专项任务才作为专家显示。知识用于理解业务术语、状态和歧义，工单证据仍是标签依据，也不能增加用户未要求的条件。

没有 Wiki、没有匹配专家或可用专家失败时，通用 Agent 仍能完成检索。先验用于提出有依据的检查方向，可以被当前工单否定，不作为工单事实来源。

发现分歧时需要可解释的处置。证据不足的工单继续待查；不能靠多数专家同意、相似度高或自动全选进入确认集合。分歧解决策略属于可替换设计，见 [运行与专家](design/AGENT_RUNTIME.md)。

## 5. 工单分层与大集合

工单保留 L0–L3 分层，主 Agent 和专家默认依据标题、摘要和结构化字段判断，足以判定的直接确认或排除，不把原文读取作为逐条必经步骤。只有摘要缺少决定性事实、已有材料矛盾、疑难业务边界，或用户明确要求核实原文/处理过程时，才说明疑点并定向读取少量候选的最小必要字段；已有共享证据直接复用。不能以“保险起见”为由逐条读完整对话。摘要可作为概览依据，不冒充原文已核实。层级、字段与证据身份定义见 [上下文规划](design/CONTEXT.md)。

候选可能有几百到几千条。完整集合保存在后台；前端分页/有限呈现，模型每轮只读取当前工作集。旧轮次以引用、必要标题和简短判断压缩保留，重要旧证据能重新展开。不能把每轮全部工单和详情一直追加进上下文，也不能通过删除未处理候选掩盖容量问题。

自定义检索对当前完整召回并集完成二分类，最终是集合交付。一般证据问答的有界窗口与后续专家研究不改变本固定流程，不以首屏或未审候选代替结果。

## 6. 交互与持续运行

用户立即看到已取得的候选，随后能观察新增、复核、确认、排除、专家检查和当前缺口。证据侧栏显示依据与不确定性，不展示未经验证的百分比“置信度”。最终 UI 方式以可理解、可操作的工作台体验验收。

运行期间可继续对话、提交补充或回答问题。需要澄清的工作等待对应回复，其他独立工作继续；问题持久化并能在回到页面后回答。只展示简短行动理由和证据，不要求模型公开内部完整思考过程。

常见业务含义和普通相关性由 Agent 依据 Wiki、工单及已给信息自决；只有缺少用户独有且实质改变交付的信息才询问。已回答口径持续有效。举例、引用工单内容、描述用户所在地不能被编译为新的工单地域条件；补充解释沿用候选与已读证据，只重审受影响判断，不重跑首轮快查。独立专家委派后主 Agent 可继续工作，结果逐个合并。

任务运行或等待回答时，空输入框的主按钮为黑色圆形停止键；输入文字后变为发送箭头，清空恢复停止键。用户停止立即取消主 Agent、专家和待答问题，保存已产生的结果与轨迹；普通工具错误返回可恢复说明，由模型继续纠偏，只有可复现的无进展重复循环才中止。

检索、证据读取、相关性核查和确认由 Agent 自动推进。界面不得把“待复核”变成强制用户处理的待办或交付门槛，也不要求用户逐条审核才能得到报告和下载。用户默认直接消费持续形成的确认结果；内部未判定状态可以在可选的检索过程里说明，不转嫁为用户任务。确需用户明确业务范围时才提出澄清，其他独立检索继续。

逐条“相关/不相关”标记及理由是**可选的、供 Agent 复核的反馈**。查看依据和反馈问题不属于必经步骤。Agent 可以修订判断，也可以据证保留判断，但应向用户说明处理结果。用户明确修改查询条件时，所有受影响候选重新确认资格；不能把条件修改降格为可忽略建议。

关闭页面、刷新、断线不取消后台检索。再次进入能恢复已有结果、进度与待回答问题。首版承诺浏览器生命周期与任务解耦；进程崩溃后的恢复可靠性也需要设计和验收，不能将“Session 可重放”当作后台任务已恢复执行。

取消或故障暂停后的“恢复检索”沿用当前查询条件、确认结果与筛选进度，不创建新的查询条件代次，也不重置抽样额度。恢复操作与补充业务条件分别提交。

## 7. 停止、确认与报告

| 概念 | 用户语义 |
| --- | --- |
| 历史候选 | 曾检索到，用于追溯，不保证符合最新要求 |
| 当前候选 | 当前范围内待分析的工单，尚不等于相关 |
| 确认结果 | 自定义检索的教师或最终模型判断为是；不等于人工已审核或根因已被独立证实 |
| 未判定 | 尚缺证据或存在未解决分歧，只用于过程和后续复核 |
| 排除 | 依据当前条件或业务判断不纳入，保留原因与来源 |

**最终报告和下载只交付确认结果。** 新报告及其导出由确认数量、一至两段简短业务总结和必要引用构成，不附工单清单或长段原文；引用保留身份并能按需打开。新报告只进行一次模型写作调用，不另发模型 review，不自动重写重试；引用仍通过结果成员和来源身份检查。模型失败或用户取消时保留工件状态，允许用户显式重试；已生成报告保持可读。此规则只约束报告生成，自定义筛选仍仅固定128工单的一轮S2标注。

Agent 根据已检查范围、新增有效证据、未解决歧义和继续动作的价值决定停止。关键词当前查询枚举完、达到用户数量、语义范围充分是不同结论。没有完整标签或可证明边界时，不宣称“全局找全”或计算真实语义召回率。

用户明确只要若干条时遵循数量目标，不凑数；要求全部时优先覆盖与遗漏检查。默认以问题覆盖组织检索，不把一个固定 Top-K 当作用户默认期望。

每个查询条件代次的初判与命中复核累计最多 128 次独立判断；当前流程将额度用于一轮选样，不另做独立抽验。批量请求、技术重试和 token 用量分别计量；重试复用同一工单判断身份，不重复占用独立判断额度。恢复沿用已取得标签。未达原目标采用最佳已训练模型；选择集查准率低于 60% 或额度内依据不足时显示“不知道”，仅交付已确认工单。调用次数、输入/输出 token、QPM、TPM 与耗时只计量，不以累计阈值中止。取消、权限、上下文容量和服务故障仍如实表达未完成。

结束可能是满足当前检索目标，也可能是资源/服务问题导致未完成。两者都如实解释，不能到 3 分钟自动宣布成功。新检索作业保存有效结束结果后，自动排入默认“工作查阅”检索报告；报告、界面和下载使用同一已确认结果版本。读取已有任务只恢复已保存的状态、过程与工件，不重新发起模型生成；后续补充与复核产生可追溯的新版本。

## 8. 自动积累经验

系统从经复核的纠正和检索经验自动更新 Wiki，供后续任务使用。系统需要提炼适用范围、依据、例外及反例，自动校验和发布增量；无需用户逐条审核。

复核后的反馈、成功与失败轨迹可以提供学习材料，但用户反馈、模型自评和重复出现次数都不是单独的真值保证。自动学习需要版本、引用、冲突修复与可回退能力；发生错误时可停用/修订错误条目并继续基础检索。详见 [Wiki 与学习](design/KNOWLEDGE.md)。

## 9. 示例数据与适用范围

默认 19,587 条 ESFT JSONL 用于试用和流程验证。日期、地区、状态缺失；规则生成的产品、类别等也不代表真实业务标签。真实数据接入后需重新验证查询语义与效果。

报告模板、下载字段、业务字段映射和部署资源应结合使用场景配置。质量评估需要代表性数据及独立标签，不能将示例数据上的流程表现外推为业务质量承诺。

## 10. 日常运行与模型设置

日常启动应复用已有容器镜像、模型、数据和索引，并让安装/升级操作可明确区分。工作台直接配置和选择 DSH 支持的供应商及模型，包括 OpenAI 兼容 API 和本机 Ollama，保留 OpenCode Go 会话 header 兼容。

检索完成优先，时间与累计上下文消耗不是自动结束任务的理由；接近模型窗口时自动压缩并继续，界面显示当前用量和压缩情况。工具调用错误应留在 ReAct 循环内，让模型根据明确字段和错误说明纠偏；只有无有效进展的重复循环才中止，不设固定错误/动作/模型请求次数截止。界面另展示累计输出 token 消耗，区别于当前上下文窗口。历史记录可移除并撤销，模型与供应商入口位于侧栏底部。真正无法恢复的供应商/协议/容量问题须明确未完成，不能假称找到全部。用户补充后历史轨迹仍可查看，当前结果资格按新条件复核。主/专家查询是可调用工具，其实际执行应在过程中可见。
