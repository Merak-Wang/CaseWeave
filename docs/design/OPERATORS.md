# Python 语义算子与现有 Host

语义入口只有 `sem_filter`、`sem_extract`、`sem_agg`。搜索和读取是基础工具；确定性集合运算、排序和统计由普通代码执行。一次任务只需要 filter 时不执行抽取或聚合。Python 使用现有 DSH 模型回调，不创建第二个 Agent、标签服务或质量 Agent。

| 入口 | 输入与结果 | 使用边界 |
| --- | --- | --- |
| sem_filter | 完整业务判据与当前召回候选并集 → 确认集合及质量对象 | 默认对关键词 OR 全部字面命中与语义召回结果按工单身份去重后的并集学习筛选；显式指定候选或示例任务可直接判断少量记录 |
| sem_extract | 明确所需记录、字段/schema → 有字段来源的事实 | 字段读取和可靠解析优先；开放事实通过现有 DSH reader，不按簇传播金额、日期或原因 |
| sem_agg | 所给事实/证据 → 代码统计与有来源的说明 | 证据窗口不改变集合；总体精确统计必须有全部所需字段 |

`sem_map`、`sem_topk`、`sem_join` 已退出生产工具、计划、Python 分发和实现。新的关系任务有明确需求后再设计；排名不能决定全集成员。

## 默认执行路径

`工作台任务 → task-worker/pre-step/sem_filter 工具 → SemanticOperators.filter → PythonOperatorBridge → server.Bridge.execute → invoke_rows → filter.sem_filter → online_group_filter`。

`auto` 和 `learned` 进入同一固定128学习主干。学习范围为关键词OR与语义召回去重并集；缺少数值Provider报技术失败，不回退逐条强判。公开方法包括在线 `auto` 与无反馈 `dual_description_margin`、`name_gmm`、`kmeans`，判断模式为 `compact_binary` 或 `anyjev_l0`；旧active/direct/baseline/cluster/frozen_teacher入口已退出。

Python 包的模块按职责收敛：三个算子各一文件，模型与数值块各一文件；`search.py` 保留现有一次规划与检索回调，`runtime.py` 统一模型回调、缓存和计量，`server.py` 仅提供常驻stdio服务。抽样归入 `features.py`，证据选择归入 `aggregate.py`，分发直接位于包入口。没有独立 JSONL、embedding 或 HTTP 模型适配，也没有第二套 Python 启动编排。

Python `Runtime.call` 只覆盖 `query_plan`、`sem_filter`、`sem_extract`、`sem_agg` 的模型回调；收到明确可重试的传输/超时/限流/服务端错误，或模型 JSON 结构缺少必填字段、不符合输出 schema（`OUTPUT_SCHEMA`）时，对该逻辑请求最多执行三次物理尝试，即首次加最多两次重试。默认等待 1 秒、2 秒；供应商给出更长等待提示时优先采用，但单次最多等 30 秒。每次尝试有独立调用 ID、DSH 清单和回执，实际失败、成功与 token 用量均分别计量；每次尝试前重新核验作用域，取消会打断等待。凭据、模型配置、额度等明确永久错误及未知错误不重试。JSON schema 重试不放宽引用身份、证据或业务校验；查询规划中部分计划约束另有一次带校验原因的修正机会。自定义检索的128是固定排序标注工单数，不是把初判、复核和扩标串联的独立请求额度；技术重试与AnyJev双轮的实际物理调用仍计量。该策略不是主 Agent、最终报告或所有模型调用的通用重试规则；Python 请求耗尽后返回终态错误，由 Host 结束本轮为未完成并保留确认结果，不自动重新执行整份检索作业。

模型负责判据、歧义、相关性与语义停止。Host 负责当前输入代次、授权来源、真实引用与结果发布。完整自然语言要求来自现有一次 query 理解；关键词 OR 分支完整枚举全部字面命中，语义召回分支按检索配置取结果，两者去重并集才是默认学习与预测范围。召回表达只用于发现训练样本，不替代业务判据。只有标题和摘要时按实际可见事实作是/否判断；业务不确定性体现在较低confidence，不增加第三类。用户明确要求读取而尚未取得的来源属于任务执行缺口。

同一次查询规划负责知识路由：检索 Agent 接收固定版本 Wiki 的领域目录、条目标题、适用范围与关键词，返回 `knowledge_routes`（条目 ID、业务选择理由）。规划阶段不自动注入知识正文；固定样本判断只加载选中条目的正文，空路由执行零样本判断。页面展示选择和理由；“专家与知识”还按实际 DSH 样本请求显示所携带的知识、请求次数与去重工单数，支持打开正文，独立于是否调用领域专家。没有路由的历史计划在再次执行时补做规划，不沿用固定前三条的词面搜索结果。

规划上下文区分 `search_fields`（搜索索引名）与 `evidence_fields`（可读的 L2/L3 来源字段）；后者排除摘要、生成字段、不可用字段与原始 JSON 载荷。`required_fields` 必须来自后者；旧计划要求了不可读原文字段时重新规划，不能因摘要被误列为原文而反复产生未决判断。用户明确要求但来源缺失的原文属于执行未完成，不产生教师第三类，也不自动换成摘要。

规划不把 Wiki 的取证建议升级成用户未提出的必要条件；判断时逐项核对用户明确的对象、原状态、变化及时序。部分条件有据而其他条件未被说明时仍选择更有依据的是/否并降低confidence，不能用相似主题、日期或行业惯例补足，也不能为凑足示例数量放宽条件。示例任务的关键词全集按 100 条一页枚举，模型审阅窗口和原句向量 Top-K 独立配置。

自定义检索不对教师是票再发独立复核，不要求人工逐条确认。教师输出是/否与confidence，固定前128的有效伪标签直接用于训练和择优；模型最终是集合直接进入结果和XLSX，保留判断来源以便解释。

编号核验可要求已有 `displayId`，其存在性与业务原文存在性分别判断；编号字段不能单独证明任何业务事实。

启用算子时，`ticket_decide` 只接收当前明确专家分歧的主 Agent 判断；普通候选通过 `sem_filter` 或读证后的自动筛选提交。主 Agent 不能绕过算子把缺项结果改成确认，充分时用空 judgments 提交结束动作。

明确数量的示例任务每次自动筛选只处理一个尚未判断的审阅窗口，然后交回主 Agent。已经未定的记录不因再次调用而自动重判；主 Agent 可定向读证后复核、继续下一窗口或搜索新表达。窗口结束不改变任务的未完成状态，不是总调用、时间或 token 限额，也不代表要求已满足。未给数量时，对当前关键词与语义召回去重并集执行学习式筛选。

## 数值输入与持久集合

- `featureBlock` 返回召回并集内对齐整数 IDs、连续 little-endian float32 稠密块、availability，以及可选 CSR 列块；正文不随特征读取传输。`features.take` 按小块读取有界样本池，`rows.read` 仅按标注或问答证据 IDs 读正文。
- 数据库索引准备阶段的 `prepareNumericFeatures` 将既有 Milvus 分片向量按工单聚合、归一化一次，批量写 `ra_numeric_feature`。缺向量仍保留 ID 和缺失标记。现有索引执行 `node scripts/database.mjs index` 补齐数值列；新数据执行 `pnpm db:prepare`。Provider 检查数值索引覆盖，不在查询中重建 embedding。
- 数据库 Provider 以授权 SQL 范围和数值键分页，默认 Host 传输批宽上限 2048；Python 本地可使用只读 memmap 块。当前生产表示是稠密 embedding，只有 Provider 真正提供 CSR 时才比较稀疏 SVM，不复制一套稠密向量冒充多表示。
- `predictions.begin/write/finish` 复用一份模型与质量说明。每块输出 IDs/labels/scores，`MySqlSemanticResultStore` 批量写已接受 ID，任务状态仅持有模型/集合句柄；数值结果不构造逐条 LLM 清单或重复指标报告。
- 确认页、报告计数、CSV/JSONL 下载使用同一集合句柄。分页时才映射真实工单 ID 并重新授权；报告保存有明确口径的集合哈希。点击原文和反馈只水合所需记录。新查询代次及强标签更正使旧句柄失效。

非持久示例会话使用内存集合存储，只用于小数据接线。不能据此声称跨进程恢复或 4000 万条容量。生产持久任务使用现有 MySQL TaskStore 的集合表。

## 在线二分类学习与结果发布

1. 一次LLM规划后，完整关键词OR与cosine>=0.75语义命中形成去重并集；不设低阈值Top-K保底。Provider返回真实向量及0.5cosine+0.5独立query bigram覆盖分数，标题摘要模式不混正文。
2. 完整并集按分数降序、同分稳定排序，取前128条（不足128取全部）。UI RRF种子不覆盖选样顺序；不随机探索替换这128条，不主动扩标，不做第二轮命中复核。
3. S2对固定样本输出是/否＋confidence；AnyJev可双位置读出，同一工单仍为一个二分类标注，物理调用如实计量。低confidence不弃权；技术失败不fit、不补负例。监督目标y是教师伪标签，选样分数不是y。
4. 同批有效标签训练LR、线性SVM、MLP、HGB、反馈原型和关系LR，以训练内交叉验证择优、二分类投票预测其余候选。离线独立留出只用于研究，不回流选模，不设置60%发布门槛或人工反馈前置条件。
5. 教师是票与其余最终预测是票合为结果集合，直接提供结果页和XLSX，保留teacher/model来源。不得把模型是票放入只能人工确认的proxy候选。关闭在线学习则无反馈算法直接判断整个候选并集，最终是集合同样交付。
6. 服务故障、取消或缺必要特征如实表达未完成，保留已有结果和可恢复状态。重放不能重复标注已完成的固定样本；研究分数、confidence、投票比例与相关分数均不宣称为校准人工准确率。

## 抽取与问答

`sem_extract(field_map=...)` 直接解析已送达的来源字段，缺失或不可解析时返回 undetermined；先用 `ticket_read` 取得确实需要的字段。开放事实调用实际 DSH reader，非空字段各有引用，不沿相似关系复制事实。

`sem_agg(numeric_fields=...)` 先统计所给记录的 present/missing/observed_sum。缺字段时不生成精确 sum/mean；代码结果和覆盖口径送入实际 DSH writer。当前该接口统计命名输入记录，未自动扫描任意整个确认集合的所有业务字段；局部字段结果不能冒充总体精确统计。

`evidence_window` 仅对已确认、命名的有界证据池执行 MMR 多样性选择。池内相关性已由 filter 判定，窗口按等相关度选择不同向量；不将模型分数当概率。返回 `selected_evidence_only` 与 Host 提供的总体数量，不截断 filter 集合。需要针对新问题更相关的池时，先用现有 search/read 取得所需证据。

分层摘要只传子摘要、来源 ID 和父关系；独立索引保存叶证据，最后物化所引用叶子的来源。最终引用列表仍随所引用证据量增长，当前证据窗口用于控制解释规模，不能把局部摘要宣称为全部记录的事实统计。
