# 检索工作台、报告与下载

数据库工作台提供主对话、专家依据、异步问题、服务端分页、检索报告与持久 CSV/JSONL/Markdown 工件。任务与文件生成由 Host 的持久租约驱动，关闭页面不取消。DSH 结果面板另提供同步 CSV 接口。

## 1. 页面与信息层次

以任务为工作单位：搜索首页、最近任务、确认结果与检索进展、按需证据侧栏、报告及下载。上述视图现已运行于正式 `/retrieval`。默认突出当前查询、已确认工单与新的有效进展；对话用于补充条件。检索与核查由 Agent 自动完成，不能设置强制用户处理的“待复核”选项、逐条审批或人工确认交付门槛。证据展开和反馈是可选操作，内部未判定状态放在可选的检索过程中，不作为用户待办。

| 区域 | 主要内容 | 用户可执行操作 |
| --- | --- | --- |
| 任务导航 | 当前/历史任务、运行或待答状态 | 打开并恢复任务，明确发起新任务 |
| 主工作区 | 原始需求、当前范围、确认工单、简短进展 | 直接使用结果、分页、随时补充与修订条件 |
| 专家进展 | 正在核查的领域/问题、发现与争议 | 查看工作依据、补充领域信息 |
| 证据侧栏 | 所选工单的原文、引用、纳入依据与证据状态 | 按需详情、可选的相关/不相关反馈 |
| 报告页 | 当前确认集合的解释、范围、引用与下载 | 查看引用、直接下载当前确认结果、补充后由 Agent 继续检查 |

工作台采用暖白底、深灰主按钮与青绿色引用强调，主内容分为“工单结果 / 检索过程 / 检索报告”。[模板](../../packages/product-host/src/workbench.ts)、[样式](../../packages/product-host/src/workbench-styles.ts)与[浏览器逻辑](../../packages/product-host/src/workbench-client.js)使用同一构建入口。

| 组件 | 布局与行为 |
| --- | --- |
| 查询输入 | 模式提示和发送操作放在同一输入框内；输入区约 700px，圆角 20px，发送按钮 36px，示例只填入可编辑文本 |
| 主工作区 | 主内容最大 860px，侧导航 224px；统一 20/28/40px 外边距，不让大屏正文无限拉宽；820px 以下导航可展开 |
| 结果行 | 编号、标题、两行摘要、摘要性质与“查看依据”；不重复每行确认徽标和整段判断理由，完整判断在原文抽屉中 |
| 证据 | 原文抽屉独立滚动，桌面约 530px，窄屏占可用宽度；不压缩结果列；Escape、关闭按钮恢复原焦点和文档滚动位置 |
| 状态与文案 | 首页一句引导；进度和未完成状态用短句，详细过程按需展开；回执编号、输入版本不进入默认文案，哈希收进文件详情；错误显示在当前弹层内 |
| 继续补充 | 固定在视口底部可达范围内的粘性输入区，自适应高度；Enter 发送、Shift+Enter 换行，中文输入法组合状态不触发发送 |
| 下载与报告 | 下载为独立弹层，报告保持阅读版式；完整集合、版本、数量与哈希校验继续执行，没有用户复核门槛 |
| 动效与稳定性 | 控件反馈约 150ms、抽屉入场 230ms；支持减少动态效果；结果行不循环跳动，文档承担列表滚动，翻页回到新页开头 |

来源中的序列化客服对话按“客服 / 客户”呈现。[显示转换](../../packages/product-host/src/workbench-content.js)只识别明确的 speaker/text 结构，保留其原始引用身份，并将 JSON 转义前的位置映射到显示文本；失配或落在半个转义字符中的引用不猜测高亮，未知结构按原文展示。

首页的示例只填入可编辑输入框；最近任务本地仅保存最多 20 个 ID，名称、范围及状态从重新授权快照取得。主列表固定请求 `confirmed`；首次确认前展示最多三条实际线索和通道状态，过程页按需查看 `current/history`、专家范围及分歧。标签支持方向键/Home/End，证据支持 Escape 返回引用焦点；工单正文、摘要和模型文字均以 textContent 插入。

窄屏将侧栏切成可切换面板，输入和待答问题始终可达。键盘操作、焦点、错误说明和状态变化应可访问。用户主动阅读时保留滚动位置，用新增提示替代不停重排卡片；不渲染不断增长的完整工单 DOM。

### 专家协作与生成反馈

任务上方直接展示阶段、实际用时、线索/已读原文/确认数量；进入“专家与知识”时收成短状态条，给协作图留出阅读空间。阶段由权威状态和实际读取事实推导，资源中止保留已发生步骤并明确未完成，不生成总体百分比。简单任务无需调用专家；该阶段不会强行要求用户选择或审批专家。

“专家与知识”包含主 Agent、实际分派的专家任务和汇总节点。每个专家展示领域名、分工、当前执行动作、读取片段与判断数量；只有运行中的节点和连线持续运动，完成、断线、等待和失败停止循环动效。条目由任务固定的 Wiki 发布提供；目录支持领域与关键词筛选，知识抽屉显示正文、范围、要点、限制和版本。`已引用` 仅对应当前输入代次 `measurement=dsh_request` 的知识引用记录，预载但未进入请求的条目标记 `已载入`。这证明请求包含了知识，不能独立证明模型正确应用了它。

活动流按已持久接收的输入、搜索通道状态、主 Agent 公开动作和专家执行状态增量呈现，保留阅读位置，最多保留二十条可见活动。刷新立即显示已有记录，不假装重新生成；SSE 通知驱动快照更新后，新活动短暂入场，最新公开内容渐显。报告生成使用持久工件状态显示生成占位，只有校验后的报告正文才显示。当前没有公开模型逐 token 文本通道，流式视觉不代表暴露私有推理或展示未经校验的中间结论。

`GET /api/retrieval-agent/tasks/:id/knowledge` 返回此任务固定的知识目录；`/knowledge/:entryId` 返回允许条目的正文。身份/来源在读取前后重新验证，输入代次或知识发布变化时拒绝迟到结果；浏览器不能指定发布版本、文件路径或读取发布目录之外的材料。

## 2. 即时结果与证据状态

搜索首批先显示“已检索到候选，正在核实”，不要立即把所有命中称为相关。逐步显示可核对事件，例如“关键词已枚举完”“发现仅处理记录提到跨域的工单”“正在核对套餐原因”；只有真实状态变化才播报，不用重复动画或伪造思考充当进展。

候选卡片以编号、标题、摘要片段、命中来源、当前判断和简短依据为主，深读后可高亮原片段。产品展示分开表达：

- 检索状态：哪个通道返回、枚举是否完成、是否有失败。
- 相关性：待核实、确认、排除、反馈后复核中。
- 证据状况：摘要足够、已查看处理记录、存在冲突或缺字段。
- 覆盖限制：哪些问题尚未查明、当前查询是否取完；不能称作全库召回率。

没有校准集时不显示“92% 置信度”。将来需要概率展示时，应先定义预测对象并做校准/误差评估；不能把向量分数、票数或搜索次数重新包装成概率。

当前详情字段来自重新授权的 presentation，Provider 契约统一允许 L1–L3 的受控字段并排除 raw_json。工作台与 DSH 面板复用详情客户端；数据库工作台使用持久下载客户端，旧 DSH 面板保留同步 CSV。详情按字段标签展示正文与缺失项；详情和下载错误持续可见，后台快照刷新不会把操作错误清掉。

## 3. 全双工与恢复协议

双向产品交互可以使用“HTTP 命令 + SSE 增量事件”，也可以复用经验证的 DSH 双向通信。SSE 本身是服务端推送，完整双向能力来自独立命令通道；底层选择可变，持久化契约不变。

当前公开入口为 `POST /api/retrieval-agent/tasks` 新建 query、`POST /api/retrieval-agent/tasks/:id` 提交 supplement/feedback/answer/cancel，均持久化后返回 202 和 operationId 回执。`GET /api/retrieval-agent/tasks/:id` 读取权威快照，`GET /api/retrieval-agent/tasks/:id/events?after=N` 从持久序号补发 SSE；重连接受 Last-Event-ID。接口始终解析服务端可信主体，不接收浏览器提供的权限上下文。字段定义由实际 `TaskCommand`、`CommandReceipt`、`TaskSnapshot` 和 Host 解析器维护。

工作台先读取快照再订阅；每个 change 合批传递本批最后序号和事件类型集合，按需重新读取当前投影，避免在推送事件中夹带旧工单正文。客户端以 300 ms 合并刷新并忽略重复序号，两个标签页共享后端任务且不能触发检索。任务刚入队、尚无来源快照时可以正常订阅；可重试读取失败会自动重试。GET、SSE、详情和下载均重新检查访问资格；来源失效显示原因并保留已保存输入，候选与下载不再可用。浏览器暂存未收到回执的命令并以原 operationId 重试。

SSE 的任务身份由路径绑定，change 仅带最后 `seq` 和本批 `kinds`；正文和当前判断从重新授权的快照/分页入口读取。客户端去重并拒绝串任务响应。快照与订阅衔接从快照的 eventSeq 续读，覆盖两者之间提交的事件；事件合批不是丢弃未提交输入或证据。

EventSource 重连可携带 Last-Event-ID，但刷新后的恢复还需要服务器快照和持久游标，协议本身不会替系统存事件或维持后台作业。[WHATWG SSE 规范](https://html.spec.whatwg.org/multipage/server-sent-events.html#the-last-event-id-header)。

关闭/断线只移除订阅，后台继续。两个页面重复恢复同一任务不产生两个 worker；问题、反馈回执和报告都可重建。UI 连接失败显示连接状态，不能误将其显示成检索失败。

## 4. 反馈体验

相关/不相关反馈为次要、可选操作，允许附理由，提交后显示“反馈已收到，Agent 复核中”。完成后展示改判或保留原判的证据说明；用户标记不直接改变确认状态。若影响当前判断，可暂时显示 Agent 复核中，不继续把旧判断作为最新结论；不得要求用户完成复核或逐条确认。

澄清卡片支持短选项与自由输入，不限制用户只能选模型给的选项。问题带当前业务含义和影响范围；独立搜索继续时说明其状态。用户纠正范围后显示更新后的解释，旧候选不会无提示混回。

最终结果之后的补充开启同一任务的新复核周期；保留旧版本可追溯，默认呈现最新有效结果。取消只停止本次运行，已提交的反馈、来源和有效确认结果保留。

## 5. 报告结构与依据

首版报告模板按检索交接设计，不做业务聚类或统计报表。版式可调整，但信息需要足够下游复现此次选择。

| 内容 | 来源与限制 |
| --- | --- |
| 检索结论 | 找到哪些符合要求的工单、确认数量；从冻结结果计算 |
| 查询范围 | 原始 query、用户修订、明确条件、数据代次/可用字段 |
| 代表性依据 | 从确认集合选择少量例子和决定性片段；完整集合在下载中 |
| 覆盖说明 | 执行过的检索方向、关键词枚举边界、主要限制及停止理由 |
| 使用说明 | 文件字段、来源版本、引用方法，以及确认不等于根因独立证实 |

数字、身份、范围和停止性质由结构化状态生成；模型撰写解释句并引用 EvidenceRef。报告校验引用必须属于该版本确认工单及其证据，不能引用尚未确认的工单来扩写业务结论。未解决情况以缺口说明表达，不附未判定工单清单。

没有确认结果时，报告明确“本次尚无可确认结果”并解释无字面命中、证据不足或运行失败等原因。引用校验失败时重新生成相关段落；模型服务不可用可交付结构化范围/确认列表说明，不能虚构完整叙事。

## 6. 下载接口与一致性

下载起点建议 UTF-8 CSV 供工作人员查看，JSONL 供下游程序保留结构，并附 manifest/Markdown 检索说明；具体格式可由试用调整。共同字段初始包含 ticketId、标题、摘要、必要结构字段、sourceVersion、判断理由、EvidenceRefs 和 resultRevision。JSONL 模板可携带允许交接的完整可检索正文/处理字段，供下游分析使用；字段模板由 Provider 准入，不能只能下载摘要，也不无条件包含整个内部 raw 载荷。

下载依据冻结的确认集合，后端分页/流式生成，数千条不受浏览器页宽限制。当前 CSV 已移除旧 200 条总量上限：省略 refs 下载全部确认集合，显式 refs 只能选择确认子集；Provider 每次最多读取 100 条。来源权限、快照、身份和版本在生成时重新核验，生成期间任务改版则拒绝交付。旧 `/export` 接口继续返回内存 CSV，数据库工作台改用下述持久工件；两个入口复用同一确认准入和逐页生成服务，默认 50 MB 文件资源上限。

当前 `TicketResultCollection` 为 v2，含 `resultRevision` 和逐项 judgments，移除终态 `undeterminedCandidates`；旧 Session 从权威事件重放后重新投影，不直接复用旧 UI 终态对象。下载请求必须带 resultRevision，新旧前后端需要一同构建部署。旧导出回执缺失该字段时仅作为历史审计记录保留，不能恢复下载资格；历史回执消费者迁移完毕后可移除可选字段兼容。当前结果版本使用冻结 packId；查看详情只增加阅读证据，用户补充才清除冻结结果并开启新复核。

数据库模式以 `ra_delivery` 保存规格、状态、租约、实际行数/字节数、哈希及到期时间，以 `ra_delivery_chunk` 暂存分块，以 `ra_delivery_trace` 保存重新授权的导出审计和报告实际模型请求。工件默认保留 7 天可获取资格；到期拒绝获取，尚未自动清除到期审计。每个工件的 `operationId` 为命令幂等键，绑定结果版本、格式、字段模板和报告用途；同键不同规格拒绝，失败时可显式重试。Host 替换回收过期租约，旧 fence 不能追加分块或发布，三次恢复仍未完成则明确失败。

文件先生成到私有分块，再完成版本/授权检查与短事务发布；生成过程中不能下载半份文件。获取保存文件前重新检查任务归属、当前结果、来源授权和全部确认记录，并核对分块数量、字节数和 SHA-256；HTTP 按分块发送，前端下载前再次核对版本、字节数和哈希。`manifest` 包含实际回执、报告范围和代表性引用。工件绑定 resultRevision、字段模板与内容哈希；进度、失败、重试和到期可观察。UI 显示文件对应结果版本和实际行数，不能把前端未加载当成没有更多结果。CSV 正确处理引号/换行及表格公式注入；JSONL 保留原值语义。

若部分确认工单在导出时不再可访问或版本已变化，停止该导出并提示复核，不能静默少导又沿用原数量。旧工件不可因历史生成过就绕过当前访问资格；确认集合修订后生成新工件，不覆盖旧版本含义。

## 7. 当前报告与分页接口

以下路径均位于 `/api/retrieval-agent/tasks/:taskId` 下，重新解析可信主体和结果资格；浏览器不能提供权限字段。

| 方法与路径 | 请求/响应 |
| --- | --- |
| `GET /candidates?view=current&limit=30&cursor=…` | 返回窗口 `items`、窗口判断、总数、集合版本和下一游标；view 可为 current/confirmed/history |
| `GET /experts/:expertId` | 当前输入代次的工作范围、知识引用、问题、下一动作和最多 30 条逐项依据，明确实际总数 |
| `GET /evidence?candidateRef=…` | 当前候选实际判断及最多 30 个模型可见引用，每段至多 1600 字符；保留字段、part、起止位置、来源版本与实际引用总数，不暴露授权内部字段 |
| `GET /report?resultRevision=…&audience=operator` | 独立结构化报告，优先读取同版已保存报告；audience 可为 operator/handoff |
| `POST /artifacts` | `operationId`、`resultRevision`、`kind=csv/jsonl/report`，可选 `template=summary/full`、`audience=operator/handoff`；持久接受返回 202 |
| `GET /artifacts` | 最近 20 个工件的状态、行数、字节数、哈希和到期时间，不返回正文 |
| `GET /artifacts/:id` | 当前工件状态；旧结果版本或当前访问失效时拒绝 |
| `GET /artifacts/:id/manifest` | 可保存的结构化范围、回执、报告和引用 |
| `GET /artifacts/:id/content` | 已就绪文件的分块响应；只有所有确认记录通过当前资格复核才开始发送 |

报告先用冻结集合计算数量和集合哈希，以用户输入/修订、声明字段、来源/索引代次、搜索方向、Agent 覆盖说明和仍存缺口构造事实层，最多选择五条确认工单作为代表性依据。原文引用必须同时属于该确认版本、被判断引用且实际送入模型；概览引用保留生成/来源未知性质。主 Agent 的 `satisfied` 判断与 Provider 的全库覆盖能力分别呈现，不能用 `complete=false` 把语义满足改写为未完成。

申请报告工件后，现有 DSH 模型撰写最多四段解释并引用给定 ID，另一独立请求逐句核对给定来源。引用或来源校验失败最多修正一次，仍不通过或模型不可用则保存带原因的结构化 Markdown；不能虚构成功叙事。实际请求/响应保存在私有审计表，不替代主任务判断，也不修改确认集合。两次请求可以使用同一配置模型，不能据此宣称获得不同模型共识。

## 8. 首版性能和验收

页面默认每页 30 条，服务端允许 1–100 条；`current`、`confirmed`、`history` 分开分页。快照最多携带首窗候选/确认项目和权威总数，不携带整份证据正文或全部已选引用。游标绑定集合身份、用户输入代次和当前判断，条件/判断变化返回可重试冲突，查看详情不改变游标。正文懒加载，事件合批更新。用户阅读时保留列表 DOM 和滚动位置，通过“有新进展，更新列表”显式换窗；新输入立即撤销旧列表和报告视图。结果计数由权威投影计算，不能由当前页面数组长度猜测。前端保留可重建状态，刷新不依赖内存里的工单缓存。

详情并行读取受控正文和判断引用，仅在来源版本一致、同字段/part 的实际子串与引用完全一致时高亮；未知字段单独列出，不用关键词匹配伪造判断证据。并发详情读取的本地阅读回执可以在同输入版本内重新提交，不重复 Provider I/O，也不跨输入修订重用。

每次查询、补充、问题回复、反馈和工件请求保留 operationId；丢失回执重试使用原键。快照提供已持久接收的最新回执，过程窗口提供最近反馈的接收/逐条判断处置。新输入提高最低 inputRevision 并立即清空旧资格；请求代次分别约束分页、详情、报告、工件，SSE 序号去重并合批刷新。刷新、第二标签页和页面返回都重新授权，连接中断只表示浏览器连接状态。保存文件前重新读取权威版本和确认总量，核对响应版本、实际字节数和 SHA-256；旧报告、损坏文件和未就绪工件不能触发保存。

MySQL 查找 Session 最新任务时先排序标量 ID，再按主键水合任务，避免大 JSON 参与 filesort。事务内本轮事件以实际事件计数编号；DSH 镜像从真实 Session 的连续已保存序列派生续点，仅水合缺失后缀，仍能从空 Session 恢复。领域 Controller 仍在服务端读取完整状态，不能把前端窗口上限表述为后端已实现常量内存。

验收从真实浏览器完成自然语言输入、首批展示、后台优化时反馈、专家分歧、断线/关闭后返回、最终报告引用和完整确认下载。特别测千级候选下滚动/输入响应、下载行数一致、迟到事件和两个标签页，不以组件快照替代全链路。

## 模型、上下文与持久轨迹

输入框模型选择器参考 [Perplexity 模型入口](https://www.perplexity.ai/help-center/en/articles/12802813-how-do-i-change-to-my-preferred-ai-model)，默认展示已配置模型及该模型实际支持的推理档位，二级面板管理供应商、API、凭据、模型发现和容量；不暴露完整 DSH 管理接口。任务选择写入 DSH Session，默认选择写入 DSH settings；访问任务配置仍重新授权。当前模型请求完成后，后续步骤使用新选择；重新选择同一模型保留推理档位。

过程轨迹来自 GET tasks/:id/activity 的已提交 SQL 事件投影，按 seq 增量分页；补充不清空旧轨迹，刷新可恢复旧用户输入、搜索、专家取证与结果。当前协作图仍只展示当前输入代次，历史专家状态在活动流保留。专家搜索显示真实 query，没有发生的查询不会伪造为动画。来源/权限失效时清空可见内容并拒绝历史读取。

过程节点按用户、搜索、读取、委派和提交显示图标；运行末项、阶段和任务状态使用旋转指示，专家连线显示工作状态。新增活动渐入，恢复历史直接显示，不重演生成，不强制滚动；停止/离线停止运行态指示。系统减少动态效果时关闭循环与过渡。输入框旁上下文圆环显示最近请求的输入比例，点击展开实际/估算 token、预留和压缩次数。

计时显示本轮输入到暂停/完成的时间；补充后重新计时，历史轨迹继续保留。后台累计执行计量记录暂停区间；旧记录的历史计量不改写为新的测量证据。

侧栏底部固定模型与供应商入口，历史列表单独滚动；每条历史提供删除及 8 秒撤销。从当前浏览器的历史 ID 列表移除不删除持久任务或业务工单，也不取消正在运行的任务；刷新不会自动加回。状态区分完成/未完成。输入框旁另显示输出 tokens，详情区分主 Agent 与全部历史专家输出，按供应商回执更新；未混入输入/cache tokens，报告与 Wiki 后台请求单独说明。上下文弹层区分工作集整理与容量压缩，后续触发有原因/阈值可查。

运行中或等待回答时，空白补充框的主按钮为黑色圆形停止键（白方块），有文字则切为发送箭头，清空又恢复停止。点击一次发送持久 cancel 命令，取消主/专家、撤销待答问题，保留结果与活动；取消回执丢失使用原 operationId 重试。发起停止先清掉当前任务本地尚未发出的补充，避免重连误续跑。完成后恢复普通补充入口，不显示仍在运行的指示。等待问题时只有实际存在独立专家才写“独立专家仍在继续”。

首页提供“解绑后仍合账”和“包年到期转包月”两个示例，分别填入明确查找 3 条的业务问题；按实际语料主题和现有主副卡/融合、宽带到期 Wiki 选择。首轮主/专家采用标题与摘要判断，过程第二阶段称为“审阅线索”；定向读取原文是按需动作。
