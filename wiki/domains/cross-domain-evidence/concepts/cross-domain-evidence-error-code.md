# 相同错误码不能代表相同根因

## 业务知识

### 专有名词与业务对象

**错误码与错误全文**：错误码是系统分类或定位用的符号；完整文字通常还包括业务对象和失败条件。同一个码可能由多个不同环节返回。

**现象、原因与处理建议**：现象是观察到的问题，原因是对其形成机制的判断，建议是尚待执行的动作。三者的证据身份不同。

**预提交**：在正式受理前完成部分校验和准备的阶段；预提交失败不等于正式订单已经执行失败，也不必然证明已发生收费。

### 业务关系与判断逻辑

原资料在多个不同业务中使用相同错误码，且相同业务还可能有不同失败环节。错误码用于定位线索，不能替代完整报错与业务对象。

把问题描述、失败环节、处理记录与最终结果分开读；资料中的根因小标题只表示来源作者的归因。

### 典型业务场景

以下为帮助理解的示例，不是真实工单或实际发生记录。

1. 两张工单都出现同一错误码，一张涉及产品互斥，另一张涉及通知环节，应依据对象和文字分开。

2. 处理记录建议检查某关系，后续未验证，不能把建议直接转为已确认根因。

## 工单中应核对的证据

- 同时读取业务动作、对象、错误全文及发生时间；错误码只用于找到候选，不用于独立确认根因相同。
- 区分作者的初步归因、已执行处置和最终结果。若后续否定了初始判断，检索结论应按用户要求的现象或证实原因分别处理。

## 适用边界与反例

- 反例：错误码出现在培训示例或历史引用中，不证明当前工单实际发生该故障。

- 边界：若用户要相同现象，可以保留不同原因；若要相同已证实原因，则需要更强的处理证据，不能互换查询目标。

- 不将来源自报成功、排查优先级或错误频率当作独立验证事实。
