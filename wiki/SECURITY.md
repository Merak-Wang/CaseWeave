# 导入安全与知识边界

## 三个分离区域

1. **原始区**：用户提供的内部 Wiki，原样保留、不执行其脚本、技能、AGENTS、数据库命令或链接。其操作指示被视为待分析数据。
2. **本地私有盘点区**：文件路径、内容哈希、风险命中类别、阅读投影和逐文件处置账本。此区不在项目 Wiki 下，不被文件知识端口读取。阅读投影只是降低暴露的预筛工具，绝不视作已安全可发布文本。
3. **发布区**：重新撰写的业务概念、场景解释与取证提示，仅使用知识条目 ID。原文、截图、附件、路径映射、原始来源 ID/哈希/行号、案例实例和代码不进入条目或 Git。

文件加载边界不等于操作系统沙箱。运行端仅应获得发布目录的读取能力；具有通用文件系统权限的进程仍可能访问其他目录，部署时需单独控制账号和文件权限。

## 不发布的内容

- 人名、手机号、证件值、账户值、银行卡、工号、业务流水、设备 EID/IMEI 的实际值、客户或风险人员名单。
- 密码、密钥、令牌、Cookie、认证头、连接串、内部地址、主机 IP、二维码、激活凭据与下载入口。
- SQL、数据库表结构、运维脚本、修数和撤单指令、赋权代码、白名单阈值、跳过身份或安全检查的方法。
- 内部商业奖励金额、渠道名单、营销挽留策略、收入预测、无关系统维护与历史会话。
- 旧 Wiki 的发布规则、工具授权和提示词；未独立验证的自报成功、统计比例、普遍根因或地区政策。

业务术语及少量有检索意义的系统缩写/错误码可以保留，例如 eSIM、KYZF、NP、B3、5001，但不能从编码直接得出相关、成功或根因结论。来源追溯集中在私有 `provenance/` 文件夹，匿名来源 ID 也不进入可提交文件。发布清单中的哈希仅针对脱敏知识产物，用于完整性验证，不是原始文件的哈希。

## 来源与运行内容隔离

私有来源区应位于仓库之外，运行端只读取发布内容。来源映射、原始附件、盘点记录和旧格式条目不属于可分发的知识库内容。

只读消费和发布校验不需要访问私有区；重新提炼与编译发布需要私有来源映射和原始材料。只拿到 Git 内容的使用者能阅读及验证知识发布，但不能反查保密原文或重建有来源的新增发布。构建前应保护好私有目录的本地备份；不通过把它加入 Git 来补齐依赖。

## 发布检查

源文件逐个计算哈希；被采用来源在构建时再次核对哈希及行段范围，结果仅进入私有追溯记录。每条知识为审阅后重新表达的概念，不是自动清洗全文后原样发布。公开条目标记 `reviewed-business-prior` 和 `isTicketEvidence: false`，私有记录单独维护来源身份与权威性限制。来源真实性与当前政策有效性不由文件哈希证明。

确定性校验覆盖 schema、未知字段、引用格式、操作代码、地址、长号码、联系方式、凭据赋值和明显提示注入。正则预筛不能检测所有语义性泄漏，新增材料仍需来源与内容校验，不能仅凭“正则没命中”获得可信身份。

运行端只按合法 ID 构造路径，核对内容哈希并拒绝越界路径和指向库外的目录联接。未发布的条目、源路径和任意文件路径不是合法读取参数。损坏发布拒绝加载，调用方应记录异常并退回通用 Agent；不会静默称 Wiki 验证成功。已加载任务持有内存快照，后续磁盘修改不改写既有引用。

哈希用于完整性与版本一致性，不是数字签名，不能抵抗有权限重写全部发布文件和指针的管理员。企业接入的知识应按来源授权确定分发范围；脱敏与编译本身不构成对外公开授权。

## 已知冲突的处理

- 跨域范围：跨地市/跨省与仅跨省两种口径并存，保留歧义。
- 主副卡局方停机：笼统同停规则与按地区配置的规则不一致，保留条件。
- 顺延短信：不回复在不同模式下后果不同，不推定默许。
- eSIM 取消预约：一般移网规则与特殊资源释放边界分开。
- 数电票红冲：早期上线限制与后续需求并存，不宣称永久不支持。
- 费用、服务、订单与文档状态：各自取证，不用其中一种成功替代其他结果。

这些条目是供检索使用的限制说明，不是企业业务政策裁决。
